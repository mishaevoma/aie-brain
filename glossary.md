# Glossary

The shared vocabulary. Use these terms as defined here, in conversation and in this repository. If the owner or a source uses a term differently, say so and reconcile it: adopt this definition, or change this file and the concept page together.

One line per term. The linked page has the detail and the sources.

## A–C

- **ACI (agent-computer interface)** — The tools a model works through, designed with the care given to a human interface. [Tool design](concepts/tool-design.md)
- **ADE (agentic development environment)** — One builder's name for an app that sits above harnesses and manages agent work. Not a harness. [Harness](concepts/harness.md)
- **Agent** — A model running in a loop that chooses its own steps and tool calls. Model plus harness. [Agents and workflows](concepts/agents-and-workflows.md)
- **AGENTS.md** — The vendor-neutral instruction file loaded into every session. [Instruction files](concepts/instruction-files.md)
- **Approval fatigue** — People approve so many prompts that they stop reading them. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Appropriate response rate** — Share of conversations judged acceptable at every turn against an expert rubric. Used instead of refusal rate. [Trusting eval numbers](concepts/eval-validity.md)
- **Attention budget** — Each token added to the context spends some of a limited capacity to attend. [Context engineering](concepts/context-engineering.md)
- **Augmented LLM** — A model with retrieval, tools and memory. The base unit before any workflow or agent. [Agents and workflows](concepts/agents-and-workflows.md)
- **Auto mode** — A Claude Code permission mode in which classifiers stand in for the human approver. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Behavioural eval** — A small, fast test of one observable agent behaviour, such as which tool it called. [Evals](concepts/evals.md)
- **Binary check** — A yes/no question about an output that a grader can answer. [Evals](concepts/evals.md)
- **Blast radius** — The damage an agent could do if it fails. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Blind-spot pass** — Asking a model what you are missing before you commit to an approach. [Human judgment](concepts/human-judgment.md)
- **Capability eval / regression eval** — Tasks the system mostly fails, showing what it cannot do yet / tasks it should always pass, catching breakage. [Evals](concepts/evals.md)
- **CLAUDE.md** — Claude Code's name for its instruction file. [Instruction files](concepts/instruction-files.md)
- **Code execution with MCP (code mode)** — The agent writes code that calls tools in a sandbox, so only the results it needs reach the context. [MCP](concepts/mcp.md)
- **Cognitive surrender** — Adopting an agent's output as your own view without checking it. [Human judgment](concepts/human-judgment.md)
- **Compaction** — The harness summarising its own history near the context limit and carrying on. Lossy. [Context engineering](concepts/context-engineering.md)
- **Compounding** — Turning each correction into a durable check, rule or skill. [Compounding](concepts/compounding.md)
- **Compounding skill** — A skill with a feedback loop attached, so each use can improve it. [Skills](concepts/skills.md)
- **Comprehension debt** — The gap between what a system does and what its owners understand. [Human judgment](concepts/human-judgment.md)
- **Construct validity** — Whether an eval measures the property it claims to. [Trusting eval numbers](concepts/eval-validity.md)
- **Containment** — Limiting what an agent can reach, instead of supervising each action. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Context anxiety** — A model rushing to finish as it nears what it believes is its context limit. [Long-running agents](concepts/long-running-agents.md)
- **Context engineering** — Deciding what the model sees at each step of the loop. [Context engineering](concepts/context-engineering.md)
- **Context layer (harness configuration)** — Instruction files, skills, MCP servers and memory: what you load into a harness. [Context layer](concepts/context-layer.md)
- **Context poisoning, distraction, confusion, clash** — Four ways a long context fails: an error that keeps being referenced, history that crowds out fresh reasoning, superfluous content, and parts that contradict each other. [Context engineering](concepts/context-engineering.md)
- **Context reset** — Starting a fresh agent from a written handoff, instead of compacting. [Long-running agents](concepts/long-running-agents.md)
- **Context rot** — Output getting less reliable as the input grows, with the task unchanged. [Context engineering](concepts/context-engineering.md)
- **Contextual retrieval** — Adding a short generated note on where a chunk sits in its document before indexing it. [Retrieval](concepts/retrieval.md)
- **Criteria drift** — Evaluation criteria changing as the grader sees more outputs. [Trusting eval numbers](concepts/eval-validity.md)

## D–L

- **Data plane / tool plane** — One builder's split: tools live inside the harness, MCP reaches systems outside it. [MCP](concepts/mcp.md)
- **Deferred tool loading (tool search)** — Keeping tool definitions out of context until the model searches for them. [Tool design](concepts/tool-design.md)
- **Differential test** — Running the old and new system on the same inputs and comparing. [Verification](concepts/verification.md)
- **Distractor** — A passage on the right topic that does not answer the question. It costs more than unrelated filler. [Context engineering](concepts/context-engineering.md)
- **Dreaming** — An offline pass over past sessions that corrects, reorganises and promotes memory. [Memory](concepts/memory.md)
- **Error analysis** — Reading real interactions, noting what failed, grouping the failures and counting them, to decide what to fix and what to measure. [Error analysis](concepts/error-analysis.md)
- **Eval** — A repeatable test of an AI system: tasks, trials and graders. [Evals](concepts/evals.md)
- **Eval awareness** — A model inferring that it is being evaluated and acting on it. [Trusting eval numbers](concepts/eval-validity.md)
- **Evaluation harness** — The system that runs and scores eval tasks. Different from the agent harness under test. [Evals](concepts/evals.md)
- **Evaluator** — A separate agent that grades the builder's work against criteria agreed in advance. [Long-running agents](concepts/long-running-agents.md)
- **Exfiltration** — Sending stolen data out of a system to an attacker. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Gate** — Whatever decides whether a proposed action runs: a person, a rule or a classifier. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Gold case** — An output you would actually ship, kept as a reference. [Skills](concepts/skills.md)
- **Grader** — What scores a trial: code, a model or a person. [Evals](concepts/evals.md)
- **Harness** — The software around a model that turns its text into actions: loop, tools, context management, gate, sandbox. [Harness](concepts/harness.md)
- **Harness engineering** — Building and tuning a harness, including testing how it behaves. [Harness](concepts/harness.md)
- **Hot-path memory** — Memory the agent writes while doing the task, as opposed to offline. [Memory](concepts/memory.md)
- **Idea file** — A description of a pattern written to be handed to an agent, which then builds a version that fits. [LLM wiki](concepts/llm-wiki.md)
- **Infrastructure noise** — Variation in a score caused by the execution environment. [Trusting eval numbers](concepts/eval-validity.md)
- **Initializer agent** — The first session of a long task, which sets up the run script, progress log and feature list. [Long-running agents](concepts/long-running-agents.md)
- **Injected context** — The small part of memory loaded into every session. [Memory](concepts/memory.md)
- **Instruction file** — A file loaded into every session to orient the agent. [Instruction files](concepts/instruction-files.md)
- **Intent debt** — Goals, constraints and reasons you never stated, which only you can supply. [Human judgment](concepts/human-judgment.md)
- **Interface** — What a person uses to work with an agent: CLI, app, chat surface. It may bundle a harness. [Harness](concepts/harness.md)
- **Jailbreaking** — Talking a model itself into misbehaving. A different problem from prompt injection. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Just-in-time retrieval** — The agent holds references and loads data through tools when it needs it. [Context engineering](concepts/context-engineering.md)
- **Known-good oracle** — A trusted implementation used to find where a new one fails. [Verification](concepts/verification.md)
- **Lethal trifecta** — Access to private data, exposure to untrusted content and a way to send data out, all in one agent. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **LLM wiki (wiki memory)** — A knowledge base an agent compiles from raw sources and maintains as linked files. [LLM wiki](concepts/llm-wiki.md)

## M–R

- **MCP (Model Context Protocol)** — A standard way to connect an agent to tools and data outside its harness. [MCP](concepts/mcp.md)
- **Memory** — Knowledge from experience that an agent keeps across sessions as readable context. [Memory](concepts/memory.md)
- **Meta-harness** — Infrastructure that fixes the interfaces around an agent (session, harness, sandbox) but not the loop. Also the title of a paper on improving harness code from traces. [Harness](concepts/harness.md)
- **Micro agent** — A short agent loop inside otherwise deterministic code. [Agents and workflows](concepts/agents-and-workflows.md)
- **Observe mode** — A gate that logs what it would block without blocking. [Verification](concepts/verification.md)
- **Open coding, axial coding** — Writing a free-form note on each failure, then grouping the notes into failure modes. The two steps of error analysis. [Error analysis](concepts/error-analysis.md)
- **Orchestration tax** — What your agents produce minus what you can stand behind. [Human judgment](concepts/human-judgment.md)
- **Orchestrator-workers** — A lead agent decides subtasks at run time, delegates them and merges the results. [Multi-agent systems](concepts/multi-agent-systems.md)
- **pass@k / pass^k** — The chance of at least one success in k tries / the chance that all k succeed. [Evals](concepts/evals.md)
- **Poka-yoke** — Designing a tool so that mistakes are hard to make. [Tool design](concepts/tool-design.md)
- **Programmatic tool calling** — The model calls tools from code in a sandbox, and intermediate results stay out of context. [Tool design](concepts/tool-design.md)
- **Progressive disclosure** — Loading context in layers: metadata, then body, then linked files. [Skills](concepts/skills.md)
- **Prompt injection** — An attack in which content the agent reads carries instructions for it. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Property test** — State something that must always hold and generate many inputs against it. [Verification](concepts/verification.md)
- **Rainbow deployment** — Shifting traffic gradually between versions running side by side, so running agents are not cut off. [Running agents in production](concepts/production-operations.md)
- **raw/** — The folder of unmodified source material behind an LLM wiki. [LLM wiki](concepts/llm-wiki.md)
- **Read-only action, write action** — A tool call that only observes, and one that changes something. [Tool design](concepts/tool-design.md)
- **Reasoning-blind** — Describes a judge that sees only the user's words and the proposed action, never the agent's reasoning or tool output. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)

## S–Z

- **Sandbox** — The boundary on what any action can reach: files, network, credentials. [Permissions and sandboxing](concepts/sandboxing-and-permissions.md)
- **Scaffold, scaffolding** — Older words for the code around the model. Here: the harness, or one removable part of it. [Harness](concepts/harness.md)
- **Schema** — The instruction file that tells an agent how a wiki is organised and maintained. [LLM wiki](concepts/llm-wiki.md)
- **Session log** — The durable, append-only record of everything in a run, kept outside the context window. [Long-running agents](concepts/long-running-agents.md)
- **Skill** — A folder with a `SKILL.md` and optional scripts, loaded only when a task needs it. [Skills](concepts/skills.md)
- **Split brain** — Two sets of instructions for one project drifting apart because tools read different files. [Instruction files](concepts/instruction-files.md)
- **Sprint contract** — Completion criteria agreed between builder and grader before a stage of work. [Long-running agents](concepts/long-running-agents.md)
- **Subagent** — An agent started by another agent, with its own context window. [Multi-agent systems](concepts/multi-agent-systems.md)
- **Task / trial** — A test case with inputs and success criteria / one attempt at it. [Evals](concepts/evals.md)
- **Tool loadout** — The set of tool definitions chosen for one task, instead of every tool on every call. [Tool design](concepts/tool-design.md)
- **Trace, transcript** — The full record of what an agent did in a run. [Memory](concepts/memory.md)
- **Verification loop** — The agent changes something, runs a check, reads the result and tries again before a person looks. [Verification](concepts/verification.md)
- **Verify skill** — A skill that says how to start, drive and inspect the app. [Verification](concepts/verification.md)
- **Workflow** — Model calls and tools wired together along code paths you define. [Agents and workflows](concepts/agents-and-workflows.md)
