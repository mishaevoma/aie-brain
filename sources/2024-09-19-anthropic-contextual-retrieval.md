# Introducing Contextual Retrieval

**In one line:** before you embed or index a chunk, have a cheap model write a short note placing that chunk inside its source document; retrieval failures drop sharply, and more again with reranking.

## What it says

- Plain RAG splits documents into chunks that often lose the facts needed to find them. The example is a filing chunk saying revenue rose 3% without naming the company or the quarter.
- **Contextual Retrieval** prepends a chunk-specific explanation (usually 50–100 tokens) to each chunk. It is used both before embedding (**Contextual Embeddings**) and before building the BM25 index (**Contextual BM25**).
- The context is generated by Claude 3 Haiku. The prompt passes the whole document plus the chunk and asks only for a brief situating context. Prompt caching keeps the document cached across its chunks. Assuming 800-token chunks, 8k-token documents, 50 tokens of instructions and 100 tokens of context per chunk, the one-time cost is about $1.02 per million document tokens.
- Results, measured as 1 minus recall@20 and averaged across codebases, fiction, ArXiv and science papers: Contextual Embeddings cut the failure rate 35% (5.7% to 3.7%). Adding Contextual BM25 cut it 49% (2.9%). Adding a reranker cut it 67% (1.9%).
- Hybrid search beats embeddings alone, because BM25 catches exact identifiers such as an error code like "TS-999". Results are merged with rank fusion.
- Reranking setup: retrieve the top 150 chunks, score them with the Cohere reranker and keep the top 20. Scoring more chunks costs more latency and money.
- Other findings: Gemini Text 004 and Voyage embeddings did best. Passing 20 chunks beat 10 or 5. Adding generic document summaries to chunks gained little. The authors report that every gain stacks.
- If the whole knowledge base is under about 200,000 tokens (roughly 500 pages), skip RAG and put all of it in the prompt with prompt caching.

## What to do with it

- For a small corpus, try putting the whole thing in a cached prompt before you build a retrieval pipeline.
- Use hybrid retrieval (embeddings plus BM25) as the baseline.
- Add a contextualization pass at indexing time with a small model and prompt caching. Tailor the prompt to the domain, for example with a glossary.
- Rerank a wide first pass and send about 20 chunks. Tune chunking, embedding model and counts against your own evals and latency budget.

## Terms

- **Contextual Embeddings / Contextual BM25** — embedding or lexically indexing a chunk after a generated context sentence has been prepended to it.
- **Reranking** — a second scoring pass over retrieved candidates that keeps only the most relevant ones.

## Caveats

- Published September 2024. The models it names (Claude 3 Haiku, Gemini Text 004) and the 200k-token cutoff reflect that period's context windows and prices.
- Anthropic sells the model and the prompt caching that make this approach cheap.
- The per-dataset results are only in an appendix chart and a linked PDF, which were not read. The numbers above are averages for the best-performing setup.
- A later article in this batch (2025-09-29 context engineering) describes a shift toward just-in-time agentic search alongside pre-computed retrieval like this.
