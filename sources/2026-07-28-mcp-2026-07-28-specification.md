# The 2026-07-28 Specification

**In one line:** MCP's 2026-07-28 revision drops the handshake and the transport session, so any server instance can answer any request; state travels as a handle in tool arguments, and a tool needing input mid-call asks for it and is called again.

## What it says

- **Removed.** The `initialize`/`initialized` handshake and the `Mcp-Session-Id` header are retired (SEP-2575, SEP-2567), turning a bidirectional, stateful protocol into stateless request and response.
- **In place of the handshake,** every request states its protocol version, the client's identity and its capabilities in `_meta`. A new `server/discover` call, optional for clients, returns a server's capabilities up front.
- **In place of the session,** a server that still needs state across calls mints an explicit handle in a tool, and the model passes it back as an argument. The authors prefer this to hidden transport state: the model sees the handle and can thread it between tools.
- **Behind a load balancer.** Behind an ordinary round-robin balancer any instance can serve any request, with no shared storage. Streamable HTTP requests must carry `Mcp-Method` and `Mcp-Name` headers (SEP-2243), so gateways, rate limiters and WAFs can route, authorise and meter without parsing JSON bodies.
- **Input mid-call.** Under Multi Round-Trip Requests (MRTR, SEP-2322), a tool needing a missing parameter or a confirmation returns `resultType: "input_required"` with the requests to be answered; the client makes the same call again, carrying the answers in `inputResponses`. This replaces the server-initiated `elicitation/create`, `sampling/createMessage` and `roots/list` requests, which needed a stream held open.
- **Tasks and extensions.** Tasks leave the experimental core for the `io.modelcontextprotocol/tasks` extension, with a poll-based `tasks/get` and a new `tasks/update` (SEP-2663). They join MCP Apps and Enterprise Managed Authorization under a formal extensions framework. Change notifications move to one `subscriptions/listen` stream, opted into per notification type, replacing the old HTTP GET endpoint.
- **Also.** List results carry `ttlMs` and `cacheScope` (SEP-2549) in a deterministic order, so upstream prompt caches survive a reconnect. Clients must validate the RFC 9207 `iss` parameter before redeeming a code (SEP-2468).
- **Migration.** Roots, Sampling and Logging are deprecated (SEP-2577) but work for at least twelve more months, the minimum under a new deprecation policy; the legacy HTTP+SSE transport gets a year-long off-ramp. Dynamic Client Registration (DCR) is deprecated for Client ID Metadata Documents but still works. The TypeScript, Python, Go and C# SDKs support the revision, with migration notes; Rust is in beta. The cost falls hardest on code that depended on session identifiers.

## What to do with it

- Carry state in a tool-issued handle, not in the transport session.
- Rework stream-based elicitation as an `input_required` result plus a retried call.
- Route and rate-limit on `Mcp-Method` and `Mcp-Name` at the gateway.
- Start nothing new on Roots, Sampling, Logging, HTTP+SSE or DCR.

## Terms

- **MRTR** — a result that asks for input, answered by retrying the same call.

## Caveats

- A release announcement by the lead maintainers, without measurements; about half is partner endorsements.
- It is silent on stream resumption and on requests in flight when a stream breaks; cite the linked specification changelog for those.
- "No shared storage" covers protocol state only: state behind a handle or a task still needs a home (this brain's reading; see [SEP-2663](2026-04-27-mcp-sep-2663-tasks-extension.md)).
