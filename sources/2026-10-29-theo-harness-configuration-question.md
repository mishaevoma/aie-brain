# Should T3 Code take on harness configuration?

**In one line:** The maker of a multi-harness interface asks whether it should manage skills, MCP servers and global instruction files, which names "harness configuration" as a layer of its own.

## What it says

- A one-sentence question to his audience: should T3 Code handle more "harness configuration", meaning a skill manager, an MCP marketplace, and management of global `AGENTS.md` / `CLAUDE.md` files?
- It drew 587 replies when read on 17 Nov 2026, which shows the question is live. The replies were not read.

## What to do with it

- Treat harness configuration (instructions, skills, MCP servers) as a separate layer from the harness itself. It is the part you own and the part that should move with you between tools.

## Terms

- **Harness configuration** — the user-supplied setup a harness loads: instruction files, skills, MCP servers.

## Caveats

- A question, not a position. The reason behind it is explained in his 30 Oct 2026 video: users switch harnesses inside T3 Code and are surprised that their skills do not follow.
